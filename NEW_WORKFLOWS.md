# Purchasing, credit review and individual sales tracking

Purchasing & Receiving → Waiting to be Purchased now has + New for manual requests. Add products, quantities and estimated prices, save as Draft, then Submit. Requests created from an approved Customer Order also start as Draft. Only authorized approvers can approve or reject Pending requests. Rejected requests can be edited and resubmitted. Details show line items, notes, source documents and approval history. Only Draft or Rejected requests can be edited. Approved requests can create a linked Purchase Requisition; manual requests need no Customer Order. Duplicate active linked requests and duplicate requisitions are blocked. Previous-version Waiting entries need to be submitted and approved before purchasing; they are not silently approved.

Each Biomed IS function has a compact summary above its content. Transaction screens show filtered records, drafts/rejected requests, pending approvals and approved/generated records, with document values grouped by currency where appropriate. Other pages show visible table and row counts; Outstanding adds unpaid and overdue invoice counts. Row counts represent rendered rows and follow the current view/page, while transaction record counts cover the filtered register.

Finance → Outstanding shows approved unpaid invoices and their linked approved payment receipts, credit notes and debit notes. Partial receipts reduce the balance. Different customer IDs, different currencies, pending documents and unlinked payments do not offset an invoice. Totals are grouped by currency. Due dates must be recorded to determine whether an invoice is overdue; missing due dates show Unknown. No due date is guessed from the invoice date.

Customer Order and Sales Order record Details include the same customer's outstanding invoice list before approval. Users without Outstanding view permission see a restricted message rather than a zero balance.

Staff Portal → Quotation & Tender and Sales Pipeline now show individual-entry forms and records alongside linked Biomed IS quotations. Individual records support creation, editing, filtering and removal, subject to role permissions and existing ownership/team rules. These tracking entries do not create accounting transactions. Formal quotations continue through Biomed IS.

Roles & responsibilities: System Admin receives the new permissions during startup. Grant other roles Waiting to be Purchased view/create/edit/submit/approve/reject/derive/cancel, Customer Order view/derive and Purchase Requisition view/create as required. Grant Outstanding view to finance reviewers and order approvers who should see customer balances. Outstanding view includes read access to invoices, credit notes, debit notes and receipts needed for the calculation. Pipeline create/delete grants are customizable; existing pipeline roles receive the added individual-record actions once. Previously removed permissions are retained as removed during migration.

Validation: run python3 tests/test_workflows.py and node tests/test_workflows.js. Server policy tests cover approved-only creation, duplicate prevention, source snapshots, authorization, requisition handoff, financial visibility, manual values and permission migration. JavaScript checks exercise the actual purchasing handlers and balance calculation. Native browser interaction was not available for this release.
